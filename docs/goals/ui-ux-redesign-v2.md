# 全站 UI / UX 重新设计与端到端交付

状态：2026-09-05 已完成本轮实现、端到端验收与设计文档同步。证据见 [V2交付索引](../design/redesign-v2/README.md) 与 [执行台账](../design/redesign-v2/ledger.md)。

## 目标与授权

基于 OpenDesign 原始设计规范，从用户要完成的任务出发，重新设计 Personal Design 的全部功能、全部页面、全部操作流程及其反馈、动效与异常状态，并完成实现、集成、实际浏览器验收和文档更新。交付应当使内容更容易发现、比较、查看和追溯，操作顺畅、层级清楚、视觉完整，而不只是让旧页面使用合规的颜色和圆角。

2026-09-05 用户明确反馈上一轮设计仍存在很大问题，并授权原有 UI、UX 全部调整。本目标取代上一轮关于界面形态必须保留的限制。首页横向时间轴、固定侧栏、双行自动流动、瀑布流、详情侧栏、灯箱与详情的职责划分、导航层级、入口和操作顺序都可以重新决定；没有任何既有组件因已经实现而必须保留。旧验收报告仅记录历史工程结果，不构成本轮设计认可。

设计依据为 `docs/design/open-design/rules.md` 及其引用的原始快照，继续使用 Impeccable。现有 `DESIGN.md`、页面代码和截图是待评估现状，不是不可更改的新方案。设计规范约束视觉语言、控件质量和交互纪律，不预先规定本站的页面构图与业务流程。

## 新增用户约束

用户在执行中明确：不需要全站菜单导航，首页本身承担菜单导航作用。取消侧栏与顶部产品菜单；内页保留必要的上下文返回操作和主题控制，不以另一种菜单样式变相恢复。

## 保留的产品事实

- 保留产品集门户、布局参考、灵感集的真实用途和已有内容能力；可合并重复操作或更换入口，不得静默删除能力。
- 保留内容数据包 API、上游 catalog、纠正映射、内容数据库、来源与原始 JSON、必要许可署名、现有访客可见名称约束。
- 保留双主题、键盘和触摸可用性、减少动态效果支持；保持现有零动画库约束。
- 可调整路由组织，但旧有效链接须保持可访问或明确重定向；筛选、刷新、历史和返回现场需有一致契约。
- 保护已有工作区内容，保存本轮执行基线；不通过回退仓库抹掉既有改动。不自动提交、推送或部署。

## 每项功能必须回答的问题

建立逐项台账：用户目的 → 当前问题及证据 → 新的入口/流程 → 页面与组件 → 全部适用状态 → 验收方式和结果。每个条目明确保留、重新设计、合并或替换，以及能力如何继续可达。不能用“共享组件已更新”替代对页面和流程的检查。

| 范围 | 必须重新设计的内容 |
| --- | --- |
| 全站信息架构 | 产品之间的关系、导航与定位、首页职责、跨产品跳转、桌面与手机导航、页面标题及信息层级 |
| 首页 `/` | 如何理解产品集、发现和选择产品、内容预览、进入产品、关于和署名；重新论证时间轴是否适合，允许替换 |
| 灵感列表 `/products/muse` | 内容密度和阅读顺序、分类与搜索、组合筛选、清除、数量和追加加载、媒体预览、卡片点击目的、浏览位置恢复 |
| 布局列表 `/products/layout-compositions` | 分类与主题检索、稳定浏览和比较、缺图可发现性、进入阅读；重新决定自动滚动及双行组织是否保留 |
| 灵感详情 `/products/muse/[slug]` | 图片/视频和单/多媒体的最佳观看方式、播放与切换、标题/作者/分类/描述优先级、原始出处和JSON、上一件/下一件、返回 |
| 布局详情 `/products/layout-compositions/[id]` | 图鉴阅读、放大与高清原图、分类/主题、关联内容、上一张/下一张、首尾与缺图、返回列表 |
| 媒体查看与浮层 | 明确快速预览与完整详情的分工，减少重复中转；打开、切换、关闭、缩放或手势（如采用）、焦点回归、滚动锁及连续操作 |
| 全局控件与反馈 | 主题切换、链接/按钮/输入、选中与禁用、焦点、触摸目标、系统偏好、首帧、加载与动作反馈 |
| 非正常路径 | 404、无结果、缺媒体/元数据、长内容、慢加载、失败/超时、重试、外链不可达、恢复上下文 |

从实际路由和可交互元素补齐遗漏。所有有状态功能覆盖正常、加载、空、错误、边界；同步操作不制造无意义加载。每个操作检查鼠标、键盘、触摸的适用输入和中断行为。

## 执行顺序

1. **先诊断。** 实际走完现有页面和操作，记录用户成本与设计问题，不以测试通过或token一致否认问题。检查真实图片、视频、多媒体、长标题、缺图、首尾、筛选及手机场景。
2. **先定体验，再落组件。** 提出统一的信息架构、主要任务流程、页面职责和交互模型，明确每页的主内容与主操作。给出代表性完整页面方案和可查看的预览，说明比旧方案改善了什么；不得只展示组件或配色板。无需重复请求已经授权的UI/UX变更许可。
3. **统一设计与接口。** 确定源规范下的排印、内容尺度、网格、留白、控件、响应式、媒体与动效规则；用真实内容验证页面组合。统一共享接口与文件所有权后再并行实现，避免各模块独立拼风格。
4. **并行重建设计。** 可拆分全站基础与导航、首页、灵感列表/详情、布局列表/详情、媒体与异常状态等独立子任务。每个任务负责设计、实现及行为验证；主任务负责跨页一致性和集成，不把拼接子任务结果当作交付。
5. **走完整旅程。** 从首页发现产品到检索、预览、详情、原始信息、返回和继续浏览，在桌面与手机实际操作；消除重复入口、无用中转、上下文丢失和不明确反馈。
6. **验收并交付。** 先集中进行视觉/体验复核，修正实质问题，再确认；按 Impeccable 有界检查规则停止无依据微调。更新规范和证据后才能完成目标。

## 验收门槛

### 设计与体验

- 每个页面都能说明主任务、内容优先级和操作去向；页面构图、媒体尺度、留白、层级和密度形成整体设计，不能以控件颜色正确代替。
- 每条主要流程都有改版前后对照：发现是否清楚、操作是否必要、结果是否可预期、返回是否保留上下文。保留原交互必须有适合当前任务的理由。
- 图片、视频、不同长宽比和长短文本均以真实数据检查；大面积空洞、过度包框、信息重复、主内容被控件挤占等问题需逐项判断与处理。
- 检查1440×900、1024×768、390×844及320px边界，明暗主题和缩放重排；移动端按任务重组，不仅把桌面各栏堆叠。
- 独立评审分别给出视觉构图、信息架构、操作体验、可访问性、原规范一致性的结论和证据。用户已指出的不满意不能被上一轮ship报告抵消；本轮不宣称未经用户表达的满意或认可。

### 功能与工程

- 台账中每个功能、页面、操作和适用状态有明确实现及验收结论；没有静默删减、死入口或仅供截图的模拟行为。
- 全量路由检查加代表性数据变体测试；原始出处/JSON、署名和内容事实保留。逐路由HTTP成功不冒充逐页视觉验收。
- 键盘语义、焦点、触摸、媒体控制、动态效果减少、快速重复与中断、搜索/筛选/历史/刷新/返回、失败恢复均实际验证。
- 类型检查、lint、生产构建和有意义的浏览器流程检查通过；保留可复现脚本和结果，区分真实设备、模拟设备、代码审阅与截图证据。

## 最终交付与完成条件

交付新的可运行全站、本地预览入口、全量功能/页面/操作台账、关键旅程前后对照、新设计决策与源码对应关系、独立评审及问题关闭记录、验证脚本与证据，并同步 `PRODUCT.md`、`DESIGN.md`、相关 `AGENTS.md`、设计sidecar和表面说明中受本轮改变影响的内容。

只有新设计、实现、整体验收及文档全部完成，且实质问题已解决，才可完成目标。写好目标、完成局部改色、构建成功、沿用旧截图或旧评审，都不等于本轮端到端交付。
