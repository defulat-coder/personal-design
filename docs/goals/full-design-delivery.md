# 全站设计规范对齐与端到端交付目标

状态：2026-09-05 已完成。实现、关键路径、生产构建与独立复核通过；详见 [执行台账](../design/execution/ledger.md) 和 [验收证据](../design/execution/README.md)。

## 目标

依据已迁入本项目的 OpenDesign 原始设计规范，逐项盘点并重新设计、实现和验证现有项目的每个用户可见功能、每个页面、每条操作路径及其动效与状态，交付一套视觉、组件、交互和行为一致的可运行产品。独立模块可由子任务并行完成，共享基础先统一，最终由主任务集成并完成端到端验收；仅完成文档、截图或局部页面不算目标达成。

## 设计依据及边界

- 原始设计依据：[迁移说明](../design/open-design/README.md)、[有效规则](../design/open-design/rules.md) 及其明确引用的源文件。
- 产品事实与不可丢失能力：[PRODUCT.md](../../PRODUCT.md)、根及 `apps/web/AGENTS.md`。[DESIGN.md](../../DESIGN.md) 已在交付时更新为源规范对齐后的实际实现记录；来源规则仍用于追溯。
- 复刻原规范的颜色角色、排印、圆角、控件、布局组织、CSS 归属与动效语法；保留本站产品身份与真实内容。适配须写明源规则、原因、采用值，不以视觉印象替代证据。
- 保留横向 lifeline 时间轴、内容数据包 API、分类检索、媒体浏览、原始出处与 JSON、合法署名、双主题及减少动态效果支持。
- 不改上游 catalog 内容、纠正映射或同步数据以迁就布局；不引入原项目的聊天、生成器、账户或支付业务。零动画库约束保留。
- 保留执行前未提交的改动；执行起点记录工作区差异，禁止以 reset 或整文件回退覆盖已有工作。

## 范围矩阵

下表为起始范围。执行时从实际路由、组件、可交互元素和数据变体补全，不把这张表当作忽略未列出功能的理由。

| 范围 | 页面/组件 | 必须覆盖的操作及行为 |
| --- | --- | --- |
| 全局基础 | 根 layout、tokens、基础控件、排印 | 首帧主题、主题切换与记忆、系统默认、焦点、hover/active/disabled、字体回退 |
| 全站导航 | WorkspaceShell、PageHeading | 产品间跳转、当前页状态、移动端导航、跳至内容、刷新与前进后退 |
| 首页 | `/`、HomeView、LifelineTimeline/Node | 产品浏览与进入、上线顺序、鼠标拖动、滚轮/触控板、键盘、原生横滑、进度反馈、节点滚动、关于/署名、未来节点 |
| 灵感列表 | `/products/muse`、PlateWall、CategoryTabs | 分类、查询、组合筛选、URL 状态恢复、清除/无结果、追加加载、卡片进入详情或灯箱、图像与视频呈现、可见区播停 |
| 布局列表 | `/products/layout-compositions`、LayoutWall | 分类、双向流动、悬停/焦点暂停、切换分类重置、触摸浏览、灯箱、缺图内容策略 |
| 灵感详情 | `/products/muse/[slug]`、MuseMediaCarousel | 单/多媒体、图片/视频、轮播与 snap、播放操作、前后条目、键盘导航、返回列表、作者与分类、原始出处、原始 JSON 展开及已有复制操作 |
| 布局详情 | `/products/layout-compositions/[id]`、DetailTools | 图鉴阅读/放大、高清资源/下载入口、分类与主题、上下条目、边界禁用、相关推荐、缺图提示与返回 |
| 共享媒体层 | Lightbox、autoplay hook | 从触发点打开、高清加载与失败、前后项、关闭、Esc、焦点约束与回归、滚动锁定、连续切换、减少动态效果 |
| 非正常路径 | 404、无匹配、媒体失败、缺失元数据 | 可理解说明、恢复入口、输入/筛选保留、长标题与空字段、不可用外部媒体的降级 |

每个有状态表面逐项记录 loading / empty / error / populated / edge；不适用的状态说明原因，不人为给同步静态页面制造加载过程。所有实际存在的操作都记录默认、悬停、焦点、按下、禁用及过渡行为中适用的项。

## 交付阶段与并行任务

### G0：盘点与统一契约（主任务先完成）

- 建立功能—页面—操作—状态清单，为各条目指定责任任务、来源规则和验收证据位置。
- 核对原始规范与现有实现的差异，确定 token 角色、控件 API、响应式原则和动效表。
- 定义共享组件的路径、接口、焦点/禁用语义及交互约束；页面任务在接口确定后才能集成。
- 建立执行台账，记录状态：待处理、设计已定、实现中、待验收、已通过、阻塞。不得将设计已定等同于交付完成。

### G1：共享基础（统一所有者）

- 负责 tokens、主题、字体、基础控件、全站导航和页面标题；先解决已知的颜色、按钮形态、中文负字距、动效和全局 CSS 归属差异。
- `globals.css`、根 layout、共享 primitives 由同一所有者维护；其余任务不得同时改写这些文件。
- 提供可复用组件和必要示例，让后续页面沿用相同状态规则；不制作未被产品使用的庞大组件库。

### G2–G5：独立页面与媒体任务（契约稳定后并行）

| 任务 | 负责范围 | 主要文件边界 | 依赖 |
| --- | --- | --- | --- |
| G2 首页时间轴 | 首页构图、节点、滚动与交互 | home-view、lifeline/timeline、首页路由及局部 CSS | G1 |
| G3 灵感集 | 灵感列表、详情、轮播、检索状态 | muse 路由、plate-wall、inspora-media-carousel 及局部 CSS | G1、共享筛选/媒体接口 |
| G4 布局参考 | 布局列表、详情、相关推荐及下载操作 | layout-compositions 路由、layout-wall、detail-tools 及局部 CSS | G1、共享筛选/媒体接口 |
| G5 共享交互 | 灯箱、分类控件、原始 JSON、自动播放和非正常路径 | lifeline/lightbox、category-tabs、raw-json-details、use-autoplay-video、not-found | G1 |

- 子任务均须完成自身设计、实现、针对性验证和结果说明；不得仅返回建议或未经验证的代码。
- 跨任务接口变更先向主任务提出，由文件所有者修改，再通知消费者。共享文件无多人同时写入；需要时使用隔离工作区集成。
- 并行用于独立范围，不同时实现多个互相竞争的视觉系统。共享基础未稳定时可并行只读盘点和方案分析。
- 使用当前目标内的子代理协调，不自动创建独立用户任务、发布 PR 或部署。

### G6：集成、完整用户路径与独立复核（主任务负责）

- 集成并检查全站一致性，清理重复基础样式、遗留不一致控件及不可达操作。
- 从首页实际走完产品浏览、筛选、媒体查看、详情、来源查询、返回及主题/URL 恢复链路。
- 独立复核原规则对齐、跨页一致性、可访问性和动效；修复实质问题后复验其结果。
- 最后根据实际交付更新 DESIGN.md、设计 sidecar、表面说明和已知差异表；保留原始规范快照，不改原文掩盖不一致。

## 验收标准

### 完整性

- 清单中的每个页面、功能、操作和适用状态都有实现和验证结论；无未分配条目、死按钮、仅视觉模拟的操作或静默删减功能。
- 所有动态路由经过构建/路由数据检查；按图片、视频、多媒体、长标题、缺元数据、首尾条目和缺图等变体验证模板，不能只检查一个详情页后宣称全部验证。
- 产品数据、原始出处、原始 JSON 与署名承诺完整保留；外链仅验证目标与入口，不自动向外部发送消息或发布内容。

### 设计与响应式

- 从来源规则到实现可追溯；无未说明的 token、按钮形态、排印或动效偏离。
- 桌面 1440×900、窄桌面/平板 1024×768、手机 390×844 完成检查；必要时增加实际用户视口和 320px 窄屏边界。
- 明暗主题、长内容及缩放下没有内容遮挡、不可达操作或整页意外横向溢出；时间轴等有意横滑区域不按溢出缺陷处理。
- 中文字距与行高、文本层级、图标与文字对齐、控件大小、焦点和对比度符合有效规则。

### 交互与动效

- 关键流程可用鼠标、键盘和触摸完成；焦点可见、无意外焦点陷阱，弹层关闭后回到正确位置。
- Enter/Space、Esc、方向键按控件语义生效，不抢占输入框编辑；拖动不会误触导航。
- 分类/查询、浏览器历史、刷新、主题记忆和返回现场按现有承诺工作。
- 动效具有可解释用途；进入/退出节奏明确，快速重复操作与中断不会遗留遮罩、滚动锁或失效控件。
- reduced-motion 路径仍可浏览全部内容并操作；不能关闭动效后同时失去内容或导航。
- 外部大图/视频缓慢或不可达时有合理降级，不能无限加载或把错误当作空结果。

### 工程与证据

- `pnpm --filter @personal-design/web typecheck`、改动文件 lint、`pnpm build` 通过。
- 对状态转换、数据/URL 恢复和交互回归使用有意义的测试；纯视觉检查用浏览器与截图，不为每个静态样式写重复测试。
- 提供关键路径的浏览器验证结果、代表性页面/状态截图、复核发现及关闭结果；说明未覆盖的真实限制。
- 例行检查按批进行，修复后仅复查受影响项；全部通过后停止无依据的反复微调。

## 最终交付

1. 可运行的完整实现及本地预览入口。
2. 全部范围的执行台账和验收证据索引。
3. 与实现一致的设计文档、组件约定及适配说明。
4. 构建/检查结果、独立复核结论和仍需用户处理的真实限制。

目标仅在所有必要工作完成、实质缺陷解决、证据与文档一致时标记完成。存在外部阻塞时准确记录其影响，不把局部可用称作全站交付。代码提交、推送及线上部署不由“端到端交付”自动扩展授权。
